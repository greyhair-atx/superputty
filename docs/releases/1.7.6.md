# SuperPuTTY Community Edition 1.7.6

Community-maintained fork by Chris Thornton, based on [Jim Radford's original SuperPuTTY](https://github.com/jimradford/superputty). Licensed under the MIT License. Application version: **1.7.6.0**; Windows x64 and .NET Framework 4.8.

## Changes

- Community Edition branding in the application, About dialog, installer, Start menu, and release artifact names. Original copyright and third-party notices remain intact.
- New profiles and unrecognized update-channel values use **Community fork**. Explicit upstream or community choices are preserved.
- Preferences are written to a temporary file, flushed, then atomically replace `SuperPuTTY.settings`. The previous save is retained as `SuperPuTTY.settings.bak`; interrupted writes and locked-file failures are covered by tests. Backup restoration is manual.
- `SuperPutty.exe`, namespaces, settings locations, registry paths, command-line behavior, sessions, and layout compatibility remain unchanged.

## Downloads and upgrades

Packages and scan reports are attached to the [GitHub release](https://github.com/greyhair-atx/superputty/releases/tag/sp-1.7.6):

- `SuperPuTTY-CE-1.7.6-current-user-win-x64-signed.msi`
- `SuperPuTTY-CE-1.7.6-all-users-win-x64-signed.msi`
- `VirusTotal-1.7.6.md`, `virustotal-results.json`, and `SHA256SUMS.txt`

CE packages have separate upgrade identities per scope and upgrade known community 1.6.0–1.7.5 packages in the same installation context. Ambiguous 1.5 installations require manual removal. Upstream coexistence is unsupported because legacy settings and other compatibility identifiers remain shared. See [branding and compatibility](../branding.md) before upgrading.

## Validation

Release publication is gated on completed VirusTotal analyses with zero malicious and suspicious detections for the final EXE and every shipped DLL. MSIs are not submitted to VirusTotal. The release report records per-file hashes, engine results, build/test validation, signatures, and MSI payload verification. Existing 1.7.5 reports do not apply to these binaries. Live MSI upgrade/uninstall scenarios are not covered by administrative extraction checks.
