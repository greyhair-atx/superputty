# SuperPuTTY Community Edition 1.8.0 — Signed Windows x64 Release

**LOCAL DRAFT — not published.** The prepared packages are review candidates from an uncommitted working tree. Commit the approved source and rebuild, sign, and revalidate before creating `sp-1.8.0`. Do not replace any published 1.7.x asset.

SuperPuTTY Community Edition is an independently maintained fork by Chris Thornton, based on the original [SuperPuTTY by Jim Radford](https://github.com/jimradford/superputty). This is not an official upstream SuperPuTTY release. No endorsement by Jim Radford or the PuTTY developers is implied.

## Changes

1.8.0 is the public-launch baseline for the community edition. It brings the existing CE application and dual-scope Windows installers together with a clearer landing page, installation and upgrade guides, a static project website, and staged package-manager distribution.

- Full community branding in the title, About dialog, file description, installers, shortcuts, and release names; upstream and MIT attribution retained.
- Signed x64 executable and current-user/all-users MSI packages, with signer and timestamp verification.
- Reproducible release-preparation commands, exact-byte MSI payload verification, required-artifact checks, SHA-256 manifests, and a CycloneDX runtime-file inventory.
- An allowlisted no-install ZIP that excludes private settings, debug symbols, and arbitrary developer output.
- Original `License.txt` installed alongside the third-party notices.

Maintenance improvements carried forward from 1.7.x include SCP sessions and safer one-use password delivery, updated runtime dependencies, VNC window tracking, active-session close confirmation, atomic preference saving with a previous-save backup, and community updates by default. These are existing community improvements, not all new code in 1.8.0. See [ReleaseNotes.txt](../../ReleaseNotes.txt) for the detailed history.

## Platforms and requirements

- Tested on **Windows 11 x64**. Expected to install and run on **Windows 10 x64 with .NET Framework 4.8 or later**, but Windows 10 has not been tested for this release. Windows 10 testing is **deferred with disclosed limitations** and is not a release blocker for 1.8.0. Windows 10 vendor support depends on edition and servicing arrangements; this project does not extend Microsoft's OS support.
- No x86 or native ARM64 build. ARM64 emulation and Windows Server are not validated release targets.
- Install PuTTY for SSH and PSCP for integrated SCP separately. RDP, VNC, MinTTY and other integrations require their respective clients. Command Prompt and Windows PowerShell are local-console options.
- Network authentication, server behavior and every external-client version are not covered by the isolated automated suite.

## Installation choices

| Asset | Behavior |
| --- | --- |
| `SuperPuTTY-CE-1.8.0-current-user-win-x64-signed.msi` | Local AppData installation; no administrator elevation |
| `SuperPuTTY-CE-1.8.0-all-users-win-x64-signed.msi` | Native Program Files installation; administrator approval |
| `SuperPuTTY-CE-1.8.0-portable-win-x64.zip` | Extract and run `SuperPutty.exe`; no MSI registration |
| `SuperPuTTY-CE-1.8.0-SHA256SUMS.txt` | SHA-256 values for the release assets |
| `SuperPuTTY-CE-1.8.0-sbom.cdx.json` | CycloneDX 1.6 inventory and hashes of exact ZIP runtime files |
| `SuperPuTTY-CE-1.8.0-build-manifest.json` | Source revision, dirty-tree flag and actual MSI identities |

The ZIP is a no-install distribution, **not a fully isolated portable profile**. An existing `%USERPROFILE%\SuperPuTTY.settings` takes precedence over an existing preferences file beside the executable. Sessions and layouts use the configured settings folder. External clients are not bundled.

Read the [installation guide](../manual/installation.md) and [upgrade guide](../manual/upgrading.md). Back up preferences, sessions and layouts first. Keep the same MSI scope when upgrading. Known historical community MSIs from 1.6.0 through 1.7.5 have a bounded upgrade bridge; newer CE releases retain separate scope UpgradeCodes. Ambiguous 1.5 packages require manual removal. Upstream coexistence is unsupported.

## Verify your download

In PowerShell, check the downloaded MSI before installation or the extracted executable before launch:

```powershell
Get-AuthenticodeSignature .\SuperPuTTY-CE-1.8.0-current-user-win-x64-signed.msi | Format-List
Get-AuthenticodeSignature .\SuperPutty.exe | Format-List
Get-FileHash .\SuperPuTTY-CE-1.8.0-current-user-win-x64-signed.msi -Algorithm SHA256
```

Expect `Status: Valid`, signer **Christopher Thornton**, and a nonempty `TimeStamperCertificate`. Chris Thornton is the project's publisher name; Christopher Thornton is the certificate identity. Compare the entire SHA-256 value with the corresponding filename in `SuperPuTTY-CE-1.8.0-SHA256SUMS.txt`. For the ZIP, verify its checksum and then the extracted executable's signature. ZIP/JSON/text files are not themselves Authenticode signed. Third-party DLL signatures vary; the SBOM records their exact hashes. A signature establishes publisher identity and byte integrity, not absence of vulnerabilities.

## Security and validation

See the [local preparation report](../LAUNCH-PREPARATION-REPORT.md) and [security review](../SECURITY-REVIEW-1.8.0.md) for actual results and remaining checks. No 1.8.0 binaries have been submitted to VirusTotal during this task; prior-release scan results do not describe these bytes. The [Windows 11 installer matrix](../INSTALLER-MATRIX-1.8.0.md) passed 37 operations across both scopes, including upgrades, upstream blocking and settings preservation. Windows 10 and live network-client scenarios were not validated by that matrix.

Report vulnerabilities through [SECURITY.md](../../SECURITY.md), not a public issue with sensitive details. The maintainer must confirm an operational private reporting route and enable Issues before public launch.
