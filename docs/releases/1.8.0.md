## What's new

1.8.0 is the community edition's public-launch baseline, bringing the maintained Windows session manager together with complete CE branding, clearer documentation, release verification, a static project website and staged WinGet distribution.

- Signed, timestamped Windows x64 EXE and separate current-user/all-users installers.
- Original MIT `License.txt` installed alongside complete third-party notices.
- Allowlisted no-install ZIP, versioned SHA-256 checksums, exact-payload verification and CycloneDX 1.6 runtime-file inventory.
- Improved installation, upgrade and security-reporting documentation.
- Preserved executable name, settings discovery, command-line behavior, session/layout formats and compatible community upgrade identities.

Maintenance improvements carried forward from 1.7.x include SCP sessions with safer one-use password delivery, updated dependencies, VNC window tracking, active-session close confirmation, atomic preference saves with a previous-save backup, and the community update channel by default. These are existing community improvements, not all newly introduced in 1.8.0.

## Requirements and compatibility

**Tested on Windows 11 x64. Expected to install and run on Windows 10 x64 with .NET Framework 4.8 or later, but Windows 10 has not been tested for this release.** Windows 10 testing is deferred with disclosed limitations. No x86 or native ARM64 package is provided.

Install PuTTY, PSCP and any external RDP/VNC/MinTTY clients separately as needed. Command Prompt and Windows PowerShell are supported local-console options. External client versions, live network authentication, Windows Server and ARM64 emulation are not established by the isolated test suite.

The ZIP is a no-install distribution, not a fully isolated portable profile. Existing `%USERPROFILE%\SuperPuTTY.settings` takes precedence over an existing preferences file beside the executable; sessions and layouts use the configured settings folder.

## Upgrading

Back up preferences, sessions and layouts, close SuperPuTTY, and choose the same installation scope. CE 1.7.6 upgrades normally. A fixed bridge covers known historical community MSIs from 1.6.0 through 1.7.5. Ambiguous 1.5 packages must be removed manually after backups; unknown newer packages using the historical UpgradeCode are blocked. Upstream coexistence remains unsupported because settings and some installation identifiers are shared.

## Verify before installation or launch

```powershell
Get-AuthenticodeSignature .\SuperPuTTY-CE-1.8.0-current-user-win-x64-signed.msi | Format-List
Get-AuthenticodeSignature .\SuperPutty.exe | Format-List
Get-FileHash .\SuperPuTTY-CE-1.8.0-current-user-win-x64-signed.msi -Algorithm SHA256
```

Expect `Valid`, signer **Christopher Thornton**, and a timestamp certificate. Compare the complete SHA-256 value with the corresponding filename in `SuperPuTTY-CE-1.8.0-SHA256SUMS.txt`. For the ZIP, check its hash and then the extracted EXE's signature. ZIP/JSON/text files are not Authenticode signed; third-party DLL signatures vary. The SBOM records exact payload hashes, not a complete external-client or transitive build-dependency inventory.

## Validation and security

- Complete Release/x64 solution rebuild and 142 isolated tests passed; network-dependent tests were excluded.
- Real application title, legacy layout loading, shutdown and local-console capture checks passed.
- The Windows 11 candidate installer matrix passed 37 operations across a real standard-user account and an elevated account, including upgrades, upstream blocking and preservation of settings. The final rebuild uses the same application/installer sources and passed fresh signature, version and exact-payload checks.
- Final release source: `20b78c60ec02adc0af970e2d975ef615b63e58b8`. GitHub CodeQL and Azure build 30 passed on this commit. Accessible final GitHub CI logs and local source/signing evidence were reviewed; no secret detections were found in the scans performed.
- All six final EXE/DLL VirusTotal submissions completed with **zero malicious and zero suspicious detections**. The MSI files were not submitted. See the attached report for per-file hashes, engine counts and limitations; a clean scan is not a guarantee that software has no vulnerabilities.

The checksum manifest covers the two MSIs, ZIP, SBOM and build manifest. Additional validation and VirusTotal reports accompany the release.
