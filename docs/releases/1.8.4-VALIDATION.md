## Maintainer MFA acceptance: gate closed

On November 7, 2026, the maintainer confirmed that real-server PSCP MFA works, including multiple password/token challenge-response requests, and that SSH connection sharing works with those requests. The maintainer explicitly accepted the behavior and closed this release gate. This is a maintainer-reported manual acceptance result, separate from the automated authentication/error-classification fixtures.

An independent read-only check on the development system also confirmed PSCP 0.84 could reuse an open PuTTY connection for a directory listing without another authentication prompt. A blank username failed to match the shared connection; an explicit matching username succeeded. The manual now documents this requirement and the remaining usability limitation: without connection sharing, each PSCP operation starts another connection and may prompt again; the per-operation console can appear briefly even when sharing is used.
