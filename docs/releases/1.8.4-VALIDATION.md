The tested application and installer were built from clean source commit `bd06313d6529d8686b497004bec60d7dbbf1ddd5`. These results apply to that candidate, not to a public release.

## Published MSI migration and clean signed regression follow-up

The PID-file fixture now writes to a temporary file and moves it to the readiness-marker path only after the writer has closed. The parent cannot observe an open or incomplete marker. With this test-only fix, a fresh CI-default signed-build regression run passed **397/397 tests on its first attempt, with no retries**. All 57 candidate runtime files in the test output matched the signed bundle's SBOM; application and installer bytes were unchanged.

Both published 1.8.3 MSI packages were validated against their pinned hashes before testing:

| Scope | Published MSI SHA-256 |
| --- | --- |
| Current user | `5520A1F857AB84451D5E2F212CAC4805BA79FD18A02E8833F3E8ABC0CAFC5F36` |
| All users | `CAC64BD522C4DFF97501290E62C69E55D638895C4FF5213C8412879A5512D60B` |

Each scope passed all five migration checks: install/verify the published MSI and preserve settings backups; reject Inno installation while the MSI remains installed without changing it; remove the MSI by its exact ProductCode with WinGet; install and verify the pinned 1.8.4 payload, scope, signatures, uninstaller and shortcut; launch/close the migrated application while preserving original settings. The machine test preserved four baseline settings files; the non-admin current-user test preserved two. Both runs removed their test installations completely. This validates the documented explicit uninstall/install procedure, not an automatic or atomic MSI-to-Inno upgrade.

Evidence is retained under `artifacts/release-validation-bd06313-msi-20261107/`: `signed-regression-results/signed-fixed-first-run.trx`, `vm-results/`, `vm-logs/`, `cleanup-summary.json` and `profile-cleanup.json`. Temporary tasks, the account, its profile, desktop sessions and stage write grant were removed after the follow-up tests.

## Test-run qualifications and cleanup

- The initial non-admin recovery attempt under WinRM encountered a WMI access restriction in the harness while stopping an interrupted installer. The retained journal was recovered, and the complete non-admin recovery matrix passed under a local scheduled-task token.
- The initial signed regression run hit a PID-file read/write race in `ProcessLifecycleRegressionTests.ClosingScpPresentersStopsTheirChildProcess(False)`. That initial evidence and its targeted retry remain retained; the subsequent synchronization fix and clean 397/397 signed run are recorded above.
- All test installations and recovery journals were removed, and original settings hashes were preserved. Temporary tasks, the batch-logon right, the test account and the stage write grant were removed. Windows still reported the temporary profile loaded, so its directory was retained instead of forcibly unloaded. The test-created RDP session was logged off only after verifying client-close behavior.

Raw evidence is retained locally under `artifacts/release-validation-bd06313-20261107/`: `validation-summary.json`, `vm-final-results/`, `vm-logs/`, `rdp-live/`, `signed-regression-results/` and `cleanup-summary.json`. Private environment details, credentials and raw settings backups are not included in this document.
